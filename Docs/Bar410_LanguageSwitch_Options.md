# Bar410 — แยกการสลับภาษาออกจาก Save/Replay

เขียน 2026-11-07 เป็นเอกสารให้อ่านและตอบ (ช่องตอบอยู่ท้ายไฟล์ §6) ยังไม่ได้ลงมือ
ที่มา: ใน `Bar410_Rewrite_Options.md` §11.4 เราตกลงให้สลับภาษา = reload scene แล้ว replay ไปที่ line เดิม คุณถามว่าแยกสองเรื่องนี้ออกจากกันได้ไหม

**คำตอบสั้น: ได้** และผมเสนอให้แยก (วิธี C ใน §3) เหตุผลหลักคือวิธี reload ติดข้อจำกัดของ save (Event, BeforeOpen, มินิเกม, Garnish สลับภาษาไม่ได้) ส่วนวิธีแยกสลับได้ทุกสถานะ

---

## 1. ข้อเท็จจริงที่ตรวจแล้ว

- `LineProviderBase` ของ Yarn 3.2.5 มี `LocaleCode` ที่ตั้งค่าได้ และ `GetLocalizedLineAsync(Yarn.Line line, ct)` รับ **`Yarn.Line` เดิม** (ID + ค่าที่แทนในช่อง `{$x}`) กลับไปขอข้อความใหม่ได้ ดังนั้นในทางทฤษฎี ถ้าเก็บ `Yarn.Line` ของบรรทัดที่แสดงอยู่ไว้ จะขอข้อความภาษาใหม่ของบรรทัดเดิมได้โดยไม่ต้อง replay (**ยังไม่ได้ทดลอง** ต้อง spike ว่า presenter ในโปรเจกต์เข้าถึง `Yarn.Line` ได้หรือไม่)
- ยังไม่ได้ติดตั้ง Unity Localization package
- save ที่ออกแบบไว้เก็บ **line index / ID** ไม่เก็บข้อความ (Refactor Plan Phase 4) ดังนั้น **โหลด save ข้ามภาษาได้อยู่แล้ว** แม้ไม่เกี่ยวกับการสลับภาษาระหว่างเล่น ส่วนนี้ไม่ได้ผูกกัน
- ภาษาถูกเก็บใน settings ไม่ได้อยู่ใน save slot (ตกลงแล้ว §13)

## 2. ทำไมวิธี reload + replay ผูกกับ save

มันใช้เครื่องจักรเดียวกับ Load จึงได้ข้อจำกัดเดียวกัน:
- ใช้ไม่ได้ในสถานะที่ save ไม่ได้ (Event, BeforeOpen, กลาง step ชง) และ replay กลางมินิเกมไม่ได้
- ต้องรอ R5 (save/replay) เสร็จก่อน จึงทำฟีเจอร์ภาษาไม่ได้
- ถ้า save/replay มีบั๊ก การสลับภาษาพังตามและหาสาเหตุยากขึ้น
- ฉากโหลดใหม่ state ที่ไม่อยู่ใน snapshot หาย และมี hitch จากการโหลด
- ข้อดีจริงมีข้อเดียว: ไม่ต้องกลัวข้อความที่ถูก cache ค้างภาษาเก่า เพราะทุกอย่างสร้างใหม่

## 3. ทางเลือกเมื่อแยกออกจาก save

ทั้งหมดต้องใช้กติการ่วมกัน: **ทุกที่เก็บ key (หรือ line ID) ห้ามเก็บข้อความที่แปลแล้ว** แล้วค่อยแปลตอนแสดง

### A. Reload + replay (ที่ตกลงไว้ตอนนี้)
อธิบายข้างบน

### B. สลับสดเฉพาะ UI, บทพูดเปลี่ยนที่บรรทัดถัดไป
- UI ทุกชิ้น (`LocalizedText`) ฟังเหตุการณ์เปลี่ยนภาษาแล้วอัปเดตตัวเอง
- บรรทัดที่ค้างอยู่บนจอยังเป็นภาษาเก่าจนกดไปบรรทัดถัดไป
- ง่ายสุด แต่ผู้เล่นเห็นว่าสลับไม่ครบ ("ตัวเลือกภาษาไม่ทำงาน?") โดยเฉพาะถ้าอยู่ในบรรทัดยาวหรือรอ AutoPlay นาน

### C. สลับสดทั้งหมด รวมบรรทัดที่ค้างอยู่ (แนะนำ)
- UI เหมือนวิธี B
- บรรทัดบนจอ: เก็บ `Yarn.Line` ที่กำลังแสดง เมื่อเปลี่ยนภาษา ขอข้อความใหม่จาก line provider แล้วแสดงซ้ำ ให้เลือกพฤติกรรมใน §6 (พิมพ์ใหม่ตั้งแต่ต้น หรือโชว์ข้อความเต็มทันที)
- ตัวเลือก (option) ที่แสดงอยู่: ทำแบบเดียวกัน
- ไม่ยุ่งกับ save/replay/ฉากเลย
- สลับได้ทุกสถานะรวมมินิเกม เพราะแตะแค่ข้อความ

### D. ต้องสลับจากเมนูหลักเท่านั้น
- ง่ายและเสี่ยงต่ำสุด แต่ขัดกับที่คุณระบุว่าต้องเปลี่ยนระหว่างเล่นได้

## 5. ข้อดีข้อเสียของวิธีที่แนะนำ (C) และวิธีลดความเสี่ยง

**ข้อดี**
- ไม่ติด R5 และไม่ติดกฎ "save ไม่ได้ใน Event" จึงไม่มีปัญหา O2b ที่เปิดไว้
- สลับกลางมินิเกมหรือ Garnish ได้ ไม่เสียความคืบหน้า
- save/replay ไม่ต้องรู้เรื่องภาษาเลย สองระบบทดสอบแยกกันได้
- ผู้เล่นเห็นบทพูดเปลี่ยนทันที

**ข้อเสีย / ความเสี่ยง**
1. **ข้อความที่ถูก cache:** ที่ไหนก็ตามที่เก็บ string ที่แปลแล้วจะค้างภาษาเก่า ตัวอย่างที่ผมรู้: `EventLogPresenter` เก็บข้อความและบันทึกลง save, คำอธิบายออเดอร์แบบ Detailed ที่ดึงจาก SO แล้วอาจเก็บใน `Order`, popup ที่อยู่ในคิว `EventPopupQueue` (ยังไม่ได้ไล่ครบทุกที่)
   *ลดความเสี่ยง:* กติกา "เก็บ key", `LocalizedText` component เดียว, ตรวจด้วย grep หา `string` ที่มาจากตาราง, และมีปุ่ม debug สลับ EN↔TH ใช้ไล่ทุกหน้าจอ (เพิ่มใน `GameFlowDebugHotkeys`)
2. **Text Animator ต้องประมวลผล tag ใหม่:** เปลี่ยนข้อความแล้ว effect (`[wave]` ฯลฯ) ต้องถูก parse ใหม่ และ typewriter ต้องเริ่มหรือข้ามอย่างถูกต้อง (**ยังไม่ได้ทดลอง** ต้อง spike กับ addon Text Animator for Yarn)
3. **Yarn.Line ต้องเข้าถึงได้:** presenter ปัจจุบัน (`LinePresenterCocktailProject`) ต้องเก็บ `Yarn.Line` ไว้ ถ้าไม่ได้ ต้องแก้ presenter (อยู่ในงาน R4 อยู่แล้ว)
4. **ตัวแปรที่แทนในบรรทัด** (`{$name}`) ถูกแทนตอนสร้าง `Yarn.Line` ค่าเก่าจะติดไปด้วย ซึ่งตรงกับที่ต้องการ (แสดงบรรทัดเดิมด้วยค่าเดิม) แต่ต้องตรวจว่าไม่เปลี่ยนเมื่อตัวแปรเปลี่ยนระหว่างนั้น
5. **ฟอนต์:** ต้องสลับ TMP Font Asset ต่อภาษาและคำนวณ layout ใหม่ (กล่องข้อความ, ปุ่ม, post-it) สำหรับภาษาไทยที่สูงกว่า (ความเสี่ยงของภาษาไทยอยู่ใน `Bar410_Rewrite_Options.md` §11.5 ไม่เกี่ยวกับการแยกหรือไม่แยก)
6. **ผู้เล่นกดสลับตอนพิมพ์อยู่กลางบรรทัด:** ต้องกำหนดพฤติกรรม (§6 ข้อ 2)

**ถ้าวิธี C พบปัญหาตอน spike:** ถอยไปวิธี B (ง่ายกว่า) ได้โดยไม่เสียงาน เพราะ C ประกอบด้วย B + ส่วนบรรทัดที่ค้างอยู่ ส่วนวิธี A เก็บไว้เป็นทางสำรองถ้า R5 เสร็จ
